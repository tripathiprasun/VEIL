About VEIL


          

            
VEIL is a browser-only steganography workstation. Everything — image decoding, encryption, embedding, extraction, hashing — runs inside this page. Nothing is uploaded anywhere.


            
Architecture

            
Vanilla HTML, CSS, and JavaScript, loaded as plain scripts rather than ES modules so the app also runs correctly when index.html is opened directly as a file:// URL. Heavy work (pixel embedding, extraction, hashing) prefers a Web Worker; most browsers block worker construction from file:// origins, so VEIL falls back to running the identical algorithm on the main thread in that case. Serve the folder over any static HTTP server to get the worker path.


            
Binary payload format

            
A small versioned container — magic bytes, version, flags, payload type, filename/MIME lengths, original size, a 16-byte salt and 12-byte IV region, filename, MIME, payload bytes, and a trailing CRC-32 — is embedded ahead of the raw pixel bits. A 32-bit length prefix on the image tells the decoder exactly how many bits to read. The decoder validates magic, version, and CRC before trusting any other field, so a corrupted or truncated image fails with a specific message instead of producing garbage output.


            
Cryptography

            
Encryption is optional and separate from hiding: steganography conceals that data exists, encryption protects what it says. When enabled, a password is stretched with PBKDF2-SHA256 (310,000 iterations) using a fresh random 16-byte salt, producing an AES-256-GCM key with a fresh random 12-byte nonce. GCM is authenticated: a wrong password and a tampered ciphertext both fail verification rather than decrypting into silent garbage. Salts, IVs, and randomness all come from crypto.getRandomValues / Web Crypto — never Math.random(), and no encryption primitive is implemented by hand.


            
Steganography

            
Mode LSB_RGB: one bit hidden in the least-significant bit of each of the red, green, and blue channels of every pixel, in row-major, R→G→B order. Alpha is left untouched. Capacity is therefore floor(width × height × 3 / 8) bytes, minus a small fixed header. PNG (and WebP) preserve these bits exactly; JPEG's lossy compression does not, so VEIL always exports PNG regardless of the input format, and warns before encoding a JPEG carrier. After every encode, VEIL immediately decodes its own output and verifies the payload round-trips correctly before reporting success.


            
Security model

            
    
              
  • Encrypted, when enabled: the payload bytes and filename/MIME metadata inside the container.
    • 
              
  • Hidden, always: the presence of a payload, from casual visual inspection of the image.
    • 
              
  • Not protected: resistance to statistical steganalysis, or protection if the image is recompressed, resized, or re-encoded after embedding — any of those will corrupt or destroy the payload.
    • 
              
  • Not provided: anonymity. Steganography hides content, not the fact that you sent someone a file.
    • 
              
  • Passwords are never stored or transmitted; they exist only in memory for the duration of a single encrypt/decrypt operation.
    • 
            


            
Supported formats

            
Input: PNG, WebP, JPEG (JPEG is decoded for inspection only — re-export is always PNG). Output: PNG.
